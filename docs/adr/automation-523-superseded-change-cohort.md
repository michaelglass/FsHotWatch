# Retain admitted changes across model supersession

A cold command integration test exposed overlapping discovery and change processing. An incremental batch captured model generation 2, then a newer discovery invalidated it before its final batch publication. The publication guard correctly refused stale evidence. The changes owner retained that refusal as a terminal failure even after a separate scan completed against the newer model, so the command could not produce a complete verdict.

Model supersession now has a specific exception type. An incremental request retries only that refusal while retaining its original ownership, changes and preprocessor-suppression snapshot. Each attempt captures the current project model, options and dependency graph; the existing publication guard still covers source results and the final batch seal. Explicit scans continue to refuse invalidated publication, and genuine errors remain terminal.

Content admission belongs to the request, not its attempts. The per-daemon content tracker advances when it admits a path. Asking it again during recovery would classify the already admitted input as unchanged and could settle without doing the owed analysis. The request therefore remembers each path's original admission decision until completion. This does not reset the global tracker or admit unrelated inputs. Existing cancellation and operation deadlines remain in effect.

The regression uses real FCS analysis and an injected watcher callback. A preprocessor barrier holds the original source after content admission; explicit discovery replaces the model before release. No second file event is sent. On the original implementation the owner retains a failure. With recovery it produces exactly one full-check result and one batch seal for that original source at generation 2, then settles without an owner fault. Existing explicit-scan refusal and genuine failure controls remain unchanged in meaning.

The test-first revision d7dff213 produced 104 passes and one expected failure. The correction passed all 105 daemon tests and all four real cold-command integration controls, with no skips. These focused results do not replace canonical CI or the complete integration gate. Partial results emitted before supersession still carry their original model generation; recovery does not promote them into a current-model seal.
